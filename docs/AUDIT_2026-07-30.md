### Priority rule

Priority is derived from **severity × user impact × prerequisite value ×
operational risk**, never from audit category (the retired proposal put
low-severity comment edits at P1 and CI coverage at P5 purely because of their
category).

| P | Meaning |
|---|---|
| **P1** | Reachable security exposure or data loss, **or** a prerequisite that unblocks other work. |
| **P2** | Correctness defect with user-visible, data-integrity, or loop-integrity impact. |
| **P3** | Missing regression protection for shipped behaviour, or documentation that actively misleads. |
| **P4** | Maintainability / architecture with no user-visible impact. |
| **P5** | Cosmetic documentation accuracy. |

(IF NOT EXISTS )?\"?video\"?\b" lexy-app/backend/migrations/versions` returns
nothing, while `016:16` runs `ALTER TABLE video DROP COLUMN …`.

**Consequence:** CLAUDE.md §11's documented bootstrap (`alembic upgrade head`
as the whole setup) cannot build a working database. A fresh developer
database, a CI database, and a disaster-recovery restore all fail at revision
006 — roughly a third of the schema is unreconstructible from the repository.

**Why implementation cannot safely begin:** the obvious fix — append a
`CREATE TABLE IF NOT EXISTS` migration after 036 — is structurally invalid.
Alembic applies revisions in linear order, so a migration appended *after* 036
never runs before 006 fails on an empty database. A correct repair needs either
a baseline revision inserted *before* the first dependent ALTER or an explicit
migration-chain repair, and **neither can be authored without knowing the real
column/constraint definitions of those ten tables.** Guessing them would
produce a schema that silently differs from production — worse than the current
honest failure. Migrations are also append-only by project rule
(`CLAUDE.md` §12), so inserting a baseline revision is a documented process
exception that only a human can grant.

**What would unblock it (all three required):**
1. A schema-only dump of the ten tables from an environment representative of
   production — `pg_dump --schema-only -t video -t video_category …`.
2. A decision on the repair shape: insert a baseline revision before the first
   dependent ALTER, or repair the chain in place.
3. Explicit permission for the append-only-migrations exception that either
   choice requires.
